# 每日 Summary 模板（精简可审计版）

本模板用于生成 `投资新闻归档/YYYY-MM/YYYY-MM-DD/summary_YYYY-MM-DD.md`。

日报是**组合监控、历史对比和证据定位的运行摘要**；同日 HTML 是**完整阅读与决策解释页**。两者共享同一份 `raw_data/`、`item_summaries/` 和持仓快照，但职责不同：日报不得把 HTML 的完整新闻、全量市场表和逐基金推理再复制一遍，也不能因此丢失后续历史读取所需的状态。

---

## 一、使用原则

### 1. 时间视角与数据口径

- 若日报在 `T` 日早晨生成，复盘对象是 `T-1` 的官方净值、ETF 收盘、北向单日与近 7 天窗口。
- 基金数据用前一交易日官方净值；ETF 用前一交易日收盘日线；不使用估值、分析日当天 ETF spot 或当天北向数据。
- `今日关注要点` 写 `T` 日当天最先验证什么，不写成“明日关注”。
- 缺失字段必须明确标注缺口，禁止估算补写。

### 2. 分层与依赖关系

1. **事实源**：`raw_data/*.json`、`item_summaries/*.md`、`投资者行动/持仓情况.md`。HTML 和日报均不是事实源。
2. **日报**：保存完整核心持仓表、持仓变化、组合结论、新闻索引、市场快照、风险状态、12 只基金状态表和数据清单，供下一轮快速比对。
3. **HTML**：保存完整新闻四段式、量能/ETF/行业全表、政策表、12 张基金决策卡及完整理由/事实/边界。
4. 日报可以链接 HTML 与单条归档，但不得只剩一个 HTML 链接；历史读取不应依赖从 HTML 反向抽取状态。

### 3. 书写纪律

- 基金必须写成“基金名称(代码)”全称；禁止裸代码、简称或代码前置。
- 不把市场信息机械改写成风险结论；不把政策观察直接写成建仓或交易指令。
- 触发价格线锚定持仓成本；成本未变时，不能因单日净值上涨而上移止盈/减仓线。
- 不机械拆空章节；每章只保留后续监控所必需的信息。

## 三、各章节职责

### 一、核心指标速览与横向对比（完整保留）

本章是持仓与历史对比的稳定输入，必须包含：

- 份额大于 0 的全部基金核心表：官方净值、持有份额、当前持有金额、持仓成本、浮盈%、短期可比变化、组合占比。
- `持仓变化检测`：相对最近可比较 summary 的真实份额变化；无变化也必须明确写出。
- 2–3 句组合结论：当前强弱、稳定器状态、最需观察的仓位、为何不能直接改变动作。
- **异常横向比较**：只保留会改变动作或置信度的代理背离/相对强弱；全量代理表放 HTML。

近 1 月字段若原始数据没有可回溯值，明确写缺口，不推算。

### 二、近期重要新闻与政策（索引，不重写全文）

本章保留本轮所有 `item_summaries/` 的紧凑索引：

| 编号 | 事件锚点 | 本轮新增含义 | 归档 |
|---|---|---|---|
| 01 | 事件标题 | 对组合判断的最短用途与边界 | `item_summaries/01_xxx.md` |

- 单条归档才保存发布源、原始链接、事实、关联持仓、判断用途的完整字段。
- HTML `sec-2b` 展示完整新闻四段式。
- 北向、融资余额、成交额等脚本定量数据不得进入本章。

### 三、政策与宏观环境（结论卡）

只保留 2–4 条会影响组合判断的宏观/政策结论，且每条标明对应新闻索引或归档锚点；最后用一句话写环境判断及反向风险。

完整方向表放 HTML `sec-3b`。

### 四、宽基ETF与申万二级行业变动（市场信号快照）

必须保留：

1. 市场量能三项：两市总成交额、北向单日/窗口、融资余额及日变化。
2. 3–6 条与当前持仓有关的 ETF/行业强弱或背离信号。
3. 一句阶段判断与证据边界。

不复制全量 ETF 表、申万涨跌前后十和完整行业映射表；它们在 HTML `sec-3`，原始数据在 `market_momentum_YYYY-MM-DD.json`。

### 五、复盘与风险雷达（状态变化）

只回答：

1. 上一轮判断哪些被支持、否定或仍待验证；
2. 哪些风险新增、升级或解除；
3. 今天不做什么，以及需要满足什么条件才重新评估动作。

不重复新闻、ETF、行业原始数字。

### 六、逐基金状态复核与操作建议（12 行状态快照）

每只活跃持仓必须各占一行，至少包含：

| 基金名称(代码) | 当前状态/建议 | 本轮唯一关键信号 | 成本锚定触发线 | 置信度 | 完整卡片 |
|---|---|---|---|---|---|

- 仅保留本轮新增变化和最终状态；完整“判断理由 / 事实依据 / 信息边界”放 HTML 第四章卡片。
- 必须与核心表、HTML 目录、HTML 决策卡和第七章摘要使用同一 active holdings 集合。
- 即使没有动作变化，也必须有一行，供下一轮读取状态机。

### 七、今日关注要点（最多 3 条）

只保留当天最优先的待验证事项，例如净值/代理背离、量能连续性、基金公告或重平衡评估的前提条件。

### 八、数据附录（运行清单）

必须包含：

- 主要 `raw_data` 文件名；
- `item_summaries_count`；
- 当前持仓来源和最近可比较 summary；
- 同日完整 HTML 的相对路径；
- 关键缺口与反向证据。

## 五、交付自检

- 八章标题齐全，且第一章核心表和第六章状态表均覆盖全部 active holdings。
- 所有基金名称均为“基金名称(代码)”全称，裸代码扫描为 0。
- 第六章状态、触发线和置信度与同日 HTML 第四章/第七章一致。
- 第二章新闻索引数量 = `item_summaries_count`；每条均可定位归档。
- 第四章市场快照的定量数值可回溯至 `market_momentum`。
- 第八章列出完整 HTML 路径、raw data、最近可比 summary、缺口与反向证据。
